Most changes are cheap. A minority are catastrophic.

Blast radius computed for every file in each package, not two hand-picked ones. The gap between median and mean is the whole finding: the median change touches a handful of files, the mean is dragged upward by a small set of hub modules, and the average tells you nothing about either. The expensive minority sit inside the package's largest import cycle.

What you are looking at

The map

One square per Python file, grouped into blocks by top-level directory and ordered by path. Block size is just file count — this is a census, not a treemap of importance.

The lighting

Clicking a file runs a breadth-first walk over the reverse import edges. Squares light in waves, one wave per hop, which is exactly the order a dirty-propagation pass would visit them in.

Why it matters

A diff is what you changed; blast radius is what your change reached. A one-line edit to a hub module is a one-line diff and a several-hundred-file impact. Only the second needs a graph.

Where the data came from

Pinned source distributions from PyPI, indexed by aic — imports resolved exactly, never by suffix matching. Every number here is generated, none typed in by hand.

AIC keeps this graph on disk and updates it incrementally: index the repo once, then on each change reparse only what moved and re-mark only what the change reached. On Django that is 2.6 s once, then 51 ms to confirm nothing changed and 14–60 ms to absorb an edit — the spread being the blast radius above.

The dirty-propagation model comes from Graph-based AI Compiler (Rhodes Floyd Davis Jr., Technical Disclosure Commons, 2025, CC-BY 4.0), which runs the same machinery in the generation direction. Inspired by ideas from @rodydavis.
